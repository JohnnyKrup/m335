Der Fragenbestand

Modul 335 Mobile Applikationen. Material zum Auftrag 05C. Version 1 vom 16.08.2026.

Das hier ist kein Lesestoff und keine Lösung. Es ist Rohstoff. Auf dieser Seite steht eine einzige Java-Klasse mit dreissig Quizfragen.

Kopier sie, tipp sie nicht ab. Fragen abzutippen bringt dir nichts bei. Was du an dieser Klasse lernen sollst, steht in den drei Abschnitten darunter, und das sind zusammen zwölf Zeilen.

Wozu du sie brauchst

Bis 05B lagen sieben Fragen in deiner GameActivity, alle aus der Kategorie Technologie. Ab 05C wählst du vor jeder Runde eine Kategorie. Damit in jeder Kategorie eine Runde von fünf Fragen aufgeht, braucht es mehr Fragen und mehr Kategorien.

KategorieFragen

zusammen30

Die Fragen stammen aus dem WISS-Quiz, das du aus den Modulen 294 und 295 kennst. Es ist derselbe Bestand, nur in Java statt in JSON.

Die drei Dinge, die du hier wirklich lesen sollst

1. Der Bestand zieht aus der Activity aus

Bis jetzt baute createQuestions() die Fragen direkt im Spielbildschirm. Das ging, solange es sieben waren. Bei dreissig wäre die GameActivity zu zwei Dritteln Daten.

Die Regel: eine Klasse hat eine Aufgabe. Die GameActivity zeigt ein Spiel an. Sie ist nicht der Ort, an dem Fragen wohnen.

2. Die Klasse wird nie erzeugt

Es gibt nirgends ein new QuestionBank(). Alle Methoden sind static, und der Konstruktor ist private. Du rufst sie über den Klassennamen auf:

QuestionBank.byCategory("Sport")

Der private Konstruktor ist kein Trick, sondern eine Ansage. Er sagt: von dieser Klasse braucht niemand ein Objekt, sie hält nur Wissen bereit.

3. Alle steht zuoberst

categories() liefert fünf Einträge, und Alle ist der erste. Das ist eine Entscheidung und kein Zufall. Alle ist der Normalfall, und der schnellste Weg soll der kürzeste sein.

byCategory behandelt diesen Eintrag darum besonders: bei CATEGORY_ALL gibt es den ganzen Bestand zurück, sonst filtert es.

Und das Unbequeme daran, das ist Absicht. Zweihundert Zeilen für dreissig Fragen. Wer eine Frage ändern will, muss die App neu bauen und neu installieren. Wer eine ergänzen will, braucht Android Studio.

Rechne das mit deiner Klasse durch: eine Lehrperson mit fünfhundert Fragen kann so nicht arbeiten. Genau darum kommt am Tag 4 eine Datenbank dazu, und danach zwei Bildschirme zum Anlegen und Bearbeiten. Erst wenn der Schmerz da war, ergibt das Sinn.

So kommt die Klasse in dein Projekt

  1. Rechtsklick auf das Paket model im Projektbaum, dann New, dann Java Class. Name QuestionBank.
  2. Den ganzen Block unten markieren und kopieren.
  3. In deiner neuen Datei alles markieren und durch das Kopierte ersetzen.

Prüf die erste Zeile. Dort steht package ch.wiss.m335.quiz.model;. Heisst dein Paket anders, passt Android Studio das beim Einfügen meist selbst an. Wenn nicht, korrigier die Zeile von Hand, sonst findet der Compiler die Klasse nicht.

 * Der Fragenbestand der App.
 *
 * Stufe 3: alle 30 Fragen stehen fest im Code. Das ist mit Absicht
 * umständlich. Wer eine Frage ändern will, muss die App neu bauen.
 * Genau darum kommt in Stufe 7 eine Datenbank dazu.
 *

public final class QuestionBank {

    /** Der Eintrag in der Auswahl, der keine Kategorie einschränkt. */
    public static final String CATEGORY_ALL = "Alle";

    /** Diese Klasse wird nie erzeugt, sie hat nur statische Methoden. */
    private QuestionBank() {
    }

    /**
     * Liefert die Einträge für die Kategorieauswahl.
     *
     * "Alle" steht bewusst zuoberst. Es ist der Normalfall, und der
     * schnellste Weg soll der kürzeste sein.
     *
     * @return die fünf Einträge in Anzeigereihenfolge
     */
    public static List<String> categories() {
        return Arrays.asList(CATEGORY_ALL, "Sport", "Technologie", "Geographie", "Geschichte");
    }

    /**
     * Liefert alle Fragen einer Kategorie.
     *
     * @param category eine Kategorie oder CATEGORY_ALL
     * @return die passenden Fragen, nie null
     */
    public static List<Question> byCategory(String category) {
        if (CATEGORY_ALL.equals(category)) {
            return createAll();
        }
        List<Question> result = new ArrayList<>();
        for (Question question : createAll()) {
            if (question.getCategory().equals(category)) {
                result.add(question);
            }
        }
        return result;
    }

Wenn du dreissig Mal questions.add(new Question(...)) untereinander siehst, ist das der Punkt. Es ist stur, es ist lang, und es funktioniert. Merk dir das Gefühl. Am Tag 4 wirst du es wiedererkennen, wenn dieselben Daten aus einer Datenbank kommen.
