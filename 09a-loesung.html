Wenn du nur einen Punkt prüfst, dann Nummer 8. Er ist der einzige, dessen Fehlen du erst beim zweiten Start siehst, und dann sieht es aus wie ein Fehler beim Anzeigen.

Beim Formular ist es Nummer 25, aus demselben Grund. Nichts stürzt ab, und der Fehler sieht aus wie ein Fehler in der Liste.

Ist ein Punkt bei dir anders und funktioniert trotzdem, entscheide selbst. Aber du solltest sagen können, warum.

Erlaubte Abweichungen

Der Code unten ist eine Lösung, nicht die Lösung. Diese Dinge dürfen bei dir anders sein, ohne dass etwas fehlt:

  • Alle Namen. Deine Klassen dürfen anders heissen, deine Methoden auch. Wichtig ist, dass ein Name sagt, was die Sache tut.
  • Die Reihenfolge der Methoden in einer Datei und die Reihenfolge der Importe. In Java ist beides egal. Im Kurs gilt das Zeitungsprinzip, also onCreate zuoberst und die Helfer darunter.
  • Die Sortierung in deiner Methode, die alle Einträge holt. Nach Laden, nach Artikel, nach id. Du musst nur sagen können, wonach.
  • Welche fünf Artikel im Startbestand stehen.
  • Ob beim Betrag eine Währung steht oder nur die Zahl.
  • Ob es einen Helfer für den Startbestand gibt oder fünfmal fünf Zeilen untereinander.
  • Ob das Formular zusätzlich einen Knopf zum Abbrechen hat. Der Zurück-Pfeil des Geräts tut dasselbe.
  • Der Wortlaut der Fehlermeldungen, solange jede beim richtigen Feld steht.
  • Ob der Standardwert für die id -1 ist wie hier oder 0 wie in 08C. Room fängt bei 1 an, beides geht.

Was nicht abweichen darf, weil es sonst still kaputt geht: das removeAllViews zuoberst, das false beim inflate, das row vor findViewById, die Prüfung mit count() im Startbestand, beim Formular das setError(null) vor der Prüfung und die Entscheidung zwischen insert und update an der id.

ShoppingItem.java

Fünf Felder, genau die aus deinem Datenmodell von 07A. Dazu die id, die Room selbst vergibt. Menge und Preis sind Integer und Double, damit sie leer sein können.

package ch.wiss.m335.einkauf.data;

import androidx.room.ColumnInfo;
import androidx.room.Entity;
import androidx.room.PrimaryKey;

/**
 * Ein Eintrag der Einkaufsliste.
 *
 * Das ist genau das Datenmodell, das du in 07A auf Papier gezeichnet hast.
 * Fünf Felder, kein Feld mehr. Der Betrag steht bewusst nicht dabei, denn er
 * ist Menge mal Preis und lässt sich jederzeit ausrechnen. Ins Datenmodell
 * gehört, was du nicht wieder ausrechnen kannst.
 *
 * Die Klasse ist zugleich die Tabelle. Die Annotation Entity sagt Room, dass
 * daraus eine Tabelle wird, und tableName gibt ihr den Namen. Ohne tableName
 * hiesse die Tabelle wie die Klasse.
 *
 * quantity und pricePerUnit sind Integer und Double, nicht int und double.
 * Der Grund steht in der Aufgabenbeschreibung: Menge und Preis können später
 * nachgetragen werden. Ein int kann nicht leer sein, es ist immer irgendeine
 * Zahl, und 0 hiesse dann null Stück statt noch nicht eingetragen. Ein
 * Integer kann null sein, und genau das brauchen wir hier.
 */
@Entity(tableName = "shopping_items")
public class ShoppingItem {

    /**
     * Die Nummer des Eintrags, von Room vergeben.
     *
     * autoGenerate = true heisst: du setzt sie nie selbst. Beim Anlegen steht
     * hier 0, und Room ersetzt die 0 durch die nächste freie Nummer.
     */
    @PrimaryKey(autoGenerate = true)
    private int id;

    /** Der Artikel, Pflichtfeld, mindestens 4 Zeichen. */
    private String article;

    /** Der Laden, Pflichtfeld, mindestens 4 Zeichen. */
    private String shop;

    /** Die Menge, darf null sein, solange sie nicht eingetragen ist. */
    private Integer quantity;

    /**
     * Der Preis pro Stück, darf null sein.
     *
     * ColumnInfo gibt der Spalte einen anderen Namen als dem Feld. In SQL
     * schreibt man Namen klein und mit Unterstrich, in Java in Binnenmajuskel.
     * Du siehst den Unterschied gleich im Database Inspector.
     */
    @ColumnInfo(name = "price_per_unit")
    private Double pricePerUnit;

    /** @return die Nummer des Eintrags */
    public int getId() {
        return id;
    }

    /** @param id die Nummer des Eintrags */
    public void setId(int id) {
        this.id = id;
    }

    /** @return der Artikel */
    public String getArticle() {
        return article;
    }

    /** @param article der Artikel */
    public void setArticle(String article) {
        this.article = article;
    }

    /** @return der Laden */
    public String getShop() {
        return shop;
    }

    /** @param shop der Laden */
    public void setShop(String shop) {
        this.shop = shop;
    }

    /** @return die Menge, oder null wenn sie nicht eingetragen ist */
    public Integer getQuantity() {
        return quantity;
    }

    /** @param quantity die Menge, oder null */
    public void setQuantity(Integer quantity) {
        this.quantity = quantity;
    }

    /** @return der Preis pro Stück, oder null wenn er nicht eingetragen ist */
    public Double getPricePerUnit() {
        return pricePerUnit;
    }

    /** @param pricePerUnit der Preis pro Stück, oder null */
    public void setPricePerUnit(Double pricePerUnit) {
        this.pricePerUnit = pricePerUnit;
    }
}

ShoppingItemDao.java

Sechs Methoden, dieselben wie im QuestionDao aus 07C. Aufgerufen werden fünf davon: getAll und count für die Liste und den Startbestand, insert beim Anlegen, findById und update beim Ändern. delete steht trotzdem da, denn ein Vertrag mit einer Tabelle wird einmal ganz geschrieben.

package ch.wiss.m335.einkauf.data;

import androidx.room.Dao;
import androidx.room.Delete;
import androidx.room.Insert;
import androidx.room.Query;
import androidx.room.Update;

import java.util.List;

/**
 * Der Zugriff auf die Tabelle shopping_items.
 *
 * Ein Dao ist ein Interface. Du schreibst nur hin, was du haben willst, und
 * Room baut die Methode dahinter beim Bauen der App selbst. Genau darum
 * braucht Room den Annotation Processor in build.gradle.kts.
 *
 * Es sind dieselben sechs Methoden wie im QuestionDao aus 07C. Das ist kein
 * Zufall. Ein Dao ist der Vertrag mit einer Tabelle, und dieser Vertrag sieht
 * bei jeder Tabelle gleich aus: anlegen, ändern, löschen, alle holen, eine
 * holen, zählen.
 *
 * Die vier Grundoperationen heissen zusammen CRUD, also Create, Read, Update
 * und Delete. Genau diese vier braucht auch die Leistungsbeurteilung.
 */
@Dao
public interface ShoppingItemDao {

    /**
     * Legt einen neuen Eintrag an.
     *
     * Die id im übergebenen Objekt wird nicht beachtet. Room vergibt eine
     * eigene und gibt sie zurück.
     *
     * @param item der neue Eintrag
     * @return die id, die Room vergeben hat
     */
    @Insert
    long insert(ShoppingItem item);

    /**
     * Speichert Änderungen an einem bestehenden Eintrag.
     *
     * Room erkennt den Eintrag an seiner id. Ist die id 0, findet Room keine
     * passende Zeile, und es passiert gar nichts.
     *
     * @param item der geänderte Eintrag, inklusive seiner id
     */
    @Update
    void update(ShoppingItem item);

    /**
     * Löscht einen Eintrag.
     *
     * Auch hier zählt nur die id.
     *
     * @param item der zu löschende Eintrag
     */
    @Delete
    void delete(ShoppingItem item);

    /**
     * Liefert alle Einträge, nach Laden und dann nach Artikel sortiert.
     *
     * Die Sortierung steht im SQL und nicht in Java. Die Datenbank kann das
     * besser, und die Liste kommt schon fertig geordnet an.
     *
     * @return alle Einträge, nie null
     */
    @Query("SELECT * FROM shopping_items ORDER BY shop, article")
    List<ShoppingItem> getAll();

    /**
     * Liefert einen einzelnen Eintrag.
     *
     * Wird beim Bearbeiten gebraucht, um das Formular zu füllen.
     *
     * @param id die Nummer des Eintrags
     * @return der Eintrag, oder null wenn es ihn nicht gibt
     */
    @Query("SELECT * FROM shopping_items WHERE id = :id")
    ShoppingItem findById(int id);

    /**
     * Zählt alle Einträge.
     *
     * Beantwortet die Frage, ob überhaupt etwas in der Tabelle steht. Beim
     * Start entscheidet sich daran, ob der Startbestand geladen werden muss.
     *
     * @return Anzahl Einträge in der Tabelle
     */
    @Query("SELECT COUNT(*) FROM shopping_items")
    int count();
}

ShoppingDatabase.java

Der Startbestand aus Schritt 2 steckt in derselben Datei. Die Zeile mit count() ist der Kern, ohne sie wächst die Tabelle bei jedem Start.

package ch.wiss.m335.einkauf.data;

import android.content.Context;
import android.util.Log;

import androidx.room.Database;
import androidx.room.Room;
import androidx.room.RoomDatabase;

/**
 * Die Datenbank der App.
 *
 * Diese Klasse ist abstract, und trotzdem entsteht daraus ein Objekt. Room
 * schreibt die fehlende Klasse beim Bauen der App selbst und nennt sie
 * ShoppingDatabase_Impl. Room.databaseBuilder liefert dann ein Objekt davon.
 *
 * Es gibt genau eine Datenbank pro App. Darum das Feld instance und die
 * Methode getInstance. Wer bei jedem Zugriff eine neue Datenbank baut,
 * verbraucht Speicher und riskiert, dass zwei Verbindungen gleichzeitig
 * schreiben.
 *
 * allowMainThreadQueries ist eine bewusste Entscheidung für diesen Kurs. Room
 * verbietet Abfragen im Haupt-Thread von sich aus, weil eine langsame Abfrage
 * die Oberfläche einfrieren lässt. Unsere Tabelle hat fünf Zeilen und liegt
 * auf dem Gerät. Bei einer echten App mit vielen Daten gehört die Abfrage in
 * einen eigenen Thread.
 */
@Database(entities = {ShoppingItem.class}, version = 1, exportSchema = false)
public abstract class ShoppingDatabase extends RoomDatabase {

    /** Log-Tag für das ganze Modul 335. */
    private static final String TAG = "Modul335";

    /** Der Dateiname der Datenbank auf dem Gerät. */
    private static final String DB_NAME = "shopping.db";

    /** Die eine Datenbank. Wird beim ersten Zugriff gebaut. */
    private static ShoppingDatabase instance;

    /**
     * Der Zugriff auf die Tabelle shopping_items.
     *
     * Auch diese Methode ist abstract. Room baut sie selbst.
     *
     * @return das Dao, über das alle Abfragen laufen
     */
    public abstract ShoppingItemDao shoppingItemDao();

    /**
     * Liefert die Datenbank und baut sie beim ersten Aufruf.
     *
     * synchronized, damit nicht zwei Aufrufe gleichzeitig je eine Datenbank
     * bauen.
     *
     * getApplicationContext ist wichtig. Eine Activity ist ein kurzlebiges
     * Objekt. Die Datenbank lebt so lange wie die App. Wer eine Activity
     * festhält, hält den ganzen Bildschirm im Speicher fest, auch wenn er
     * längst geschlossen ist.
     *
     * @param context irgendein Context, zum Beispiel eine Activity
     * @return die eine Datenbank der App
     */
    public static synchronized ShoppingDatabase getInstance(Context context) {
        if (instance == null) {
            Context appContext = context.getApplicationContext();

            instance = Room.databaseBuilder(appContext, ShoppingDatabase.class, DB_NAME)
                    .allowMainThreadQueries()
                    .build();

            seedIfEmpty();

            Log.d(TAG, "database opened, name=" + DB_NAME
                    + ", items=" + instance.shoppingItemDao().count());
        }
        return instance;
    }

    /**
     * Füllt die Tabelle beim allerersten Start mit fünf Beispieleinträgen.
     *
     * Die Bedingung count() > 0 ist der Kern dieser Methode. Ohne sie kämen
     * bei jedem Start fünf Einträge dazu, und nach fünf Starts stünden
     * fünfundzwanzig in der Liste.
     *
     * Zwei der fünf Einträge haben absichtlich keine Menge und keinen Preis.
     * So siehst du gleich beim ersten Start, dass der Betrag nur dort steht,
     * wo beides eingetragen ist.
     */
    private static void seedIfEmpty() {
        ShoppingItemDao dao = instance.shoppingItemDao();

        int existing = dao.count();
        if (existing > 0) {
            Log.d(TAG, "seed skipped, count=" + existing);
            return;
        }

        dao.insert(newItem("Vollkornbrot", "Migros", 2, 3.80));
        dao.insert(newItem("Milch", "Migros", 6, 1.65));
        dao.insert(newItem("Kaffeebohnen", "Coop", 1, 12.90));
        dao.insert(newItem("Zahnpasta", "Coop", null, null));
        dao.insert(newItem("Batterien AA", "Interdiscount", null, null));

        Log.d(TAG, "seed done, count=" + dao.count());
    }

    /**
     * Baut einen Eintrag aus vier Werten.
     *
     * Nur ein Helfer für den Startbestand. Er spart fünf mal fünf Zeilen.
     *
     * @param article      der Artikel
     * @param shop         der Laden
     * @param quantity     die Menge, oder null
     * @param pricePerUnit der Preis pro Stück, oder null
     * @return der fertige Eintrag, noch ohne id
     */
    private static ShoppingItem newItem(String article, String shop,
                                        Integer quantity, Double pricePerUnit) {
        ShoppingItem item = new ShoppingItem();
        item.setArticle(article);
        item.setShop(shop);
        item.setQuantity(quantity);
        item.setPricePerUnit(pricePerUnit);
        return item;
    }
}

     * Holt alle Einträge aus der Datenbank und lässt sie anzeigen.

    private void loadItems() {

            TextView tvShop = row.findViewById(R.id.tvShop);
            TextView tvAmount = row.findViewById(R.id.tvAmount);

            tvArticle.setText(item.getArticle());
            tvShop.setText(item.getShop());

            // Der Betrag wird gerechnet, nicht gespeichert. Fehlt ein Wert,
            // bleibt das Feld leer und zeigt nicht 0.00.
            if (item.getQuantity() != null && item.getPricePerUnit() != null) {
                double amount = item.getQuantity() * item.getPricePerUnit();
                tvAmount.setText(getString(R.string.amount_format, amount));
            } else {
                tvAmount.setText("");
            }

            // TextViews. Er öffnet das Formular und gibt die id mit. Den
            // Schlüssel gibt die Konstante im Formular vor.
            int id = item.getId();
            row.setOnClickListener(v -> {
                Intent intent = new Intent(this, ItemEditActivity.class);
                intent.putExtra(ItemEditActivity.EXTRA_ITEM_ID, id);
                startActivity(intent);
            });

            llItems.addView(row);
        }
    }

ItemEditActivity.java

Schritt 4, 5 und 6 in einer Klasse. Die id aus dem Intent entscheidet, ob angelegt oder geändert wird. Die Prüfmethode sammelt ihr Ergebnis in valid und prüft auch, ob in Menge und Preis eine Zahl steht.

package ch.wiss.m335.einkauf;

import android.os.Bundle;
import android.util.Log;
import android.widget.Button;
import android.widget.TextView;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

import com.google.android.material.textfield.TextInputEditText;
import com.google.android.material.textfield.TextInputLayout;

import ch.wiss.m335.einkauf.data.ShoppingDatabase;
import ch.wiss.m335.einkauf.data.ShoppingItem;
import ch.wiss.m335.einkauf.data.ShoppingItemDao;

/**
 * Das Formular. Ein Bildschirm für zwei Aufgaben: einen Eintrag anlegen und
 * einen bestehenden ändern.
 *
 * Welche der zwei Aufgaben läuft, entscheidet die id im Intent. Fehlt sie,
 * entsteht ein neuer Eintrag. Ist sie da, wird der Eintrag geladen, in die
 * vier Felder geschrieben und beim Speichern geändert. Ein zweiter Bildschirm
 * für das Ändern wäre doppelter Code für dieselben vier Felder und dieselbe
 * Prüfung.
 *
 * Android Studio hat die Klasse mit New, Activity, Empty Views Activity
 * angelegt. Der Insets-Block in onCreate stammt von dort und sucht die id main
 * am Root-Element von activity_item_edit.xml. Darum liegt die ScrollView im
 * Root-Element und ersetzt es nicht.
 */
public class ItemEditActivity extends AppCompatActivity {

    /** Log-Tag für das ganze Modul 335. */
    private static final String TAG = "Modul335";

    /**
     * Der Schlüssel, unter dem die id im Intent steckt.
     *
     * Eine Konstante und keine Zeichenfolge an zwei Stellen. Die MainActivity
     * legt die id unter diesem Namen ab, diese Activity holt sie darunter
     * hervor. Wer den Namen zweimal tippt, vertippt sich irgendwann, und dann
     * ist das Formular beim Antippen einer Zeile immer leer.
     */
    public static final String EXTRA_ITEM_ID = "itemId";

    /**
     * Der Wert, der bedeutet: kein bestehender Eintrag, also anlegen.
     *
     * Eine echte id ist immer grösser als 0, denn Room fängt bei 1 an. In 08C
     * steht an dieser Stelle 0, das geht genauso. Wichtig ist nur, dass beim
     * Holen und beim Speichern derselbe Wert gilt.
     */
    private static final int NO_ID = -1;

    /** Die Mindestlänge für Artikel und Laden, aus der Aufgabenbeschreibung. */
    private static final int MIN_LENGTH = 4;

    /** Das Layout um den Artikel, dort steht seine Fehlermeldung. */
    private TextInputLayout tilArticle;

    /** Das Layout um den Laden, dort steht seine Fehlermeldung. */
    private TextInputLayout tilShop;

    /** Das Layout um die Menge, dort steht ihre Fehlermeldung. */
    private TextInputLayout tilQuantity;

    /** Das Layout um den Preis, dort steht seine Fehlermeldung. */
    private TextInputLayout tilPrice;

    /** Das Eingabefeld für den Artikel. */
    private TextInputEditText etArticle;

    /** Das Eingabefeld für den Laden. */
    private TextInputEditText etShop;

    /** Das Eingabefeld für die Menge, nur ganze Zahlen. */
    private TextInputEditText etQuantity;

    /** Das Eingabefeld für den Preis pro Stück, Zahl mit Punkt. */
    private TextInputEditText etPrice;

    /**
     * Die id des bearbeiteten Eintrags, oder NO_ID beim Anlegen.
     *
     * Dieses eine Feld entscheidet an zwei Stellen: beim Füllen des Formulars
     * und beim Speichern.
     */
    private int itemId = NO_ID;

    /**
     * Baut das Formular auf und füllt es, wenn eine id mitkommt.
     *
     * @param savedInstanceState der gespeicherte Zustand, hier nicht gebraucht
     */
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_item_edit);
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });

        tilArticle = findViewById(R.id.tilArticle);
        tilShop = findViewById(R.id.tilShop);
        tilQuantity = findViewById(R.id.tilQuantity);
        tilPrice = findViewById(R.id.tilPrice);
        etArticle = findViewById(R.id.etArticle);
        etShop = findViewById(R.id.etShop);
        etQuantity = findViewById(R.id.etQuantity);
        etPrice = findViewById(R.id.etPrice);

        Button btnSave = findViewById(R.id.btnSave);
        btnSave.setOnClickListener(v -> save());

        itemId = getIntent().getIntExtra(EXTRA_ITEM_ID, NO_ID);
        if (itemId != NO_ID) {
            TextView tvEditTitle = findViewById(R.id.tvEditTitle);
            tvEditTitle.setText(R.string.title_edit);
            loadItem();
        }
    }

    /**
     * Lädt den Eintrag und schreibt seine Werte in die vier Felder.
     *
     * Menge und Preis können null sein. String.valueOf auf ein null schreibt
     * das Wort null ins Feld, darum wird vorher geprüft. Fehlt der Wert, bleibt
     * das Feld leer.
     *
     * Findet Room den Eintrag nicht mehr, gibt es nichts zu bearbeiten, und
     * der Bildschirm schliesst sich.
     */
    private void loadItem() {
        ShoppingItem item = dao().findById(itemId);
        if (item == null) {
            finish();
            return;
        }
        etArticle.setText(item.getArticle());
        etShop.setText(item.getShop());
        if (item.getQuantity() != null) {
            etQuantity.setText(String.valueOf(item.getQuantity()));
        }
        if (item.getPricePerUnit() != null) {
            etPrice.setText(String.valueOf(item.getPricePerUnit()));
        }
    }

    /**
     * Prüft das Formular und legt den Eintrag an oder ändert ihn.
     *
     * Erst prüfen, dann bauen, dann schreiben. Ein leeres Feld für Menge oder
     * Preis wird zu null und nicht zu 0. Sonst stünde in der Liste ein Betrag
     * von 0.00, und der Eintrag sähe aus, als koste er nichts.
     */
    private void save() {
        if (!isValid()) {
            return;
        }

        ShoppingItem item = new ShoppingItem();
        item.setArticle(text(etArticle));
        item.setShop(text(etShop));
        item.setQuantity(text(etQuantity).isEmpty() ? null : Integer.valueOf(text(etQuantity)));
        item.setPricePerUnit(text(etPrice).isEmpty() ? null : Double.valueOf(text(etPrice)));

        // Hier entscheidet die id. Wer immer insert aufruft, bekommt beim
        // Ändern eine zweite Zeile statt einer Änderung. Nichts stürzt ab,
        // in der Liste stehen danach nur zwei fast gleiche Einträge.
        if (itemId == NO_ID) {
            long newId = dao().insert(item);
            Log.d(TAG, "item inserted, id=" + newId);
        } else {
            item.setId(itemId);
            dao().update(item);
            Log.d(TAG, "item updated, id=" + itemId);
        }
        finish();
    }

    /**
     * Prüft alle vier Felder und setzt die Meldungen an die Felder.
     *
     * Zuerst werden alle alten Meldungen entfernt. Ohne das bliebe eine
     * Meldung stehen, auch nachdem der Benutzer das Feld korrigiert hat.
     *
     * Die Methode kehrt nicht beim ersten Fehler zurück. Sie prüft alle Felder
     * und merkt sich das Ergebnis in valid. Sonst würde bei zwei falschen
     * Feldern nur das erste markiert.
     *
     * Menge und Preis dürfen leer sein. Steht etwas darin, muss es eine Zahl
     * sein. Das Feld für den Preis lässt nur Ziffern und einen Punkt zu, ein
     * einzelner Punkt ist aber keine Zahl, und parseDouble wirft dann eine
     * NumberFormatException. Das catch fängt sie ab und setzt die Meldung.
     *
     * Die Meldung gehört an das TextInputLayout und nicht in einen Toast. Nur
     * so sieht der Benutzer, welches Feld gemeint ist.
     *
     * @return true, wenn gespeichert werden darf
     */
    private boolean isValid() {
        tilArticle.setError(null);
        tilShop.setError(null);
        tilQuantity.setError(null);
        tilPrice.setError(null);

        boolean valid = true;

        if (text(etArticle).length() < MIN_LENGTH) {
            tilArticle.setError(getString(R.string.error_too_short, MIN_LENGTH));
            valid = false;
        }
        if (text(etShop).length() < MIN_LENGTH) {
            tilShop.setError(getString(R.string.error_too_short, MIN_LENGTH));
            valid = false;
        }

        String quantity = text(etQuantity);
        if (!quantity.isEmpty()) {
            try {
                Integer.parseInt(quantity);
            } catch (NumberFormatException e) {
                tilQuantity.setError(getString(R.string.error_number));
                valid = false;
            }
        }

        String price = text(etPrice);
        if (!price.isEmpty()) {
            try {
                Double.parseDouble(price);
            } catch (NumberFormatException e) {
                tilPrice.setError(getString(R.string.error_number));
                valid = false;
            }
        }

        return valid;
    }

    /**
     * Liest ein Feld und schneidet Leerzeichen am Rand weg.
     *
     * Ohne das trim bestünde ein Feld mit vier Leerzeichen die Prüfung auf
     * die Mindestlänge.
     *
     * @param field das Eingabefeld
     * @return der Inhalt, nie null
     */
    private String text(TextInputEditText field) {
        return field.getText() == null ? "" : field.getText().toString().trim();
    }

    /**
     * Kurzer Weg zum Dao.
     *
     * @return das Dao der einen Datenbank
     */
    private ShoppingItemDao dao() {
        return ShoppingDatabase.getInstance(this).shoppingItemDao();
    }
}
