Du machst deine Fragenverwaltung vollständig und stellst das Spiel auf die Datenbank um. Warum das so geht, steht in der Einführung zu 08C. private void onDeleteClicked() {
    new AlertDialog.Builder(this)
            .setTitle(R.string.dialog_delete_title)
            .setMessage(R.string.dialog_delete_message)
            .setNegativeButton(R.string.dialog_delete_keep, null)
            .setPositiveButton(R.string.dialog_delete_confirm, (dialog, which) -> deleteQuestion())
            .show();

private void deleteQuestion() {
    // Room löscht über die id. Die anderen Felder darf das Objekt leer
    // lassen, sie werden nicht angeschaut.

    question.setId(questionId);

    Log.d(TAG, "question deleted, id=" + questionId);

    finish();
}

B1Die Frage, die ihre Kategorie verloren hat. 10 Min

In A3 hast du eine Frage bearbeitet und gespeichert. Vergleich noch einmal genau mit dem, was du dir in A2 aufgeschrieben hast.

Die Frage steht nicht mehr an derselben Stelle in der Liste. Und in der kleinen Zeile darunter steht eine andere Kategorie. Aus einer Sportfrage ist eine Geographiefrage geworden, oder was bei dir zuoberst stand.

Nichts hat sich gemeldet. Kein Absturz, keine rote Meldung, kein Eintrag im Logcat. Das Speichern hat question updated, id=7 gemeldet, und das stimmt sogar.

Was ist deine Erklärung? Drei Vorschläge stehen hier, genau einer stimmt. Entscheide dich, bevor du weiterliest.

NrErklärung
1update kann die Spalte category nicht schreiben, weil sie kein Pflichtfeld ist

Die Auflösung. Nummer 2 stimmt. Schau dir deine loadQuestion an. Sie füllt den Fragetext, die vier Antworten und den Radiobutton. Die zwei Spinner kommen darin nicht vor. Ein Spinner steht darum weiter auf seinem ersten Eintrag, und onSaveClicked liest gehorsam genau das aus:

Das ist keine Schlamperei, sondern ein Muster. Ein Textfeld füllst du mit setText, und der Name der Methode sagt dir, was passiert. Ein Spinner hat kein setText. Er will eine Position und keinen Text, und darum vergisst man ihn.

Dass die Frage in der Liste gesprungen ist, war dein Glück. Dein getAll sortiert mit ORDER BY category, id. Ohne die Sortierung wäre der Fehler an derselben Stelle stehen geblieben.

Jetzt der Umbau. Du brauchst die Liste der Kategorien beim Füllen wieder. Bisher entsteht sie in onCreate und verschwindet gleich im Adapter. Mach ein Feld daraus, belege es vor den zwei setAdapter-Zeilen und benutz es in der ersten davon:

In deiner isFormValid läuft eine Schleife über alle vier Antwortfelder. Ersetz sie durch diesen Block, der Rest der Methode bleibt:

// Antwort 1 und 2 sind weiterhin Pflicht. Eine Frage mit nur einer
// Antwort ist keine Frage.
for (int i = 0; i < 2; i++) {
    if (textOf(answerFields[i]).isEmpty()) {
        answerLayouts[i].setError(getString(R.string.error_answer_required));
        valid = false;
    } else {
        answerLayouts[i].setError(null);
    }
}

// Auf Antwort 3 und 4 zeigen zwei Regeln. Zwei else würden sich
// gegenseitig löschen. Also einmal räumen, danach nur setzen.
answerLayouts[2].setError(null);
answerLayouts[3].setError(null);

// Regel 1, die Lücke. Antwort 4 ohne Antwort 3 wäre im Spiel ein
// leerer Knopf zwischen zwei gefüllten.
if (textOf(answerFields[2]).isEmpty() && !textOf(answerFields[3]).isEmpty()) {
    answerLayouts[2].setError(getString(R.string.error_answer_gap));
    valid = false;
}

// Regel 2, der Knopf oben. Steht er auf einem leeren Feld, gäbe es

Angehängt wird er mit attachToRecyclerView. Dazu die Frage, die daran hängt: brauchst du die Rückfrage trotzdem? Entscheide dich und schreib einen Satz dazu, warum. So prüfst du: Wisch eine Frage weg. Nach einem Neustart der App ist sie immer noch weg. Das ist der wichtige Punkt, denn eine Zeile aus dem Adapter zu entfernen ändert die Datenbank nicht.
