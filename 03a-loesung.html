Zum Durchlesen brauchst du etwa 10 Minuten. Das ist ein Richtwert. Du musst nicht alles lesen, such dir die Stelle, die du brauchst.

Wie du das hier benutzt. Nicht abtippen. Vergleichen. Zu jeder Lösung steht eine kurze Begründung. Die Begründung ist der eigentliche Inhalt, der Code ist nur der Beleg dazu.

Wenn deine Lösung anders aussieht und trotzdem funktioniert, ist sie richtig. Du solltest aber sagen können, warum du es anders gemacht hast.

Antworten zu den Denkfragen

Diese vier Fragen kommen im 03AB Wissenscheck als Quizfragen wieder. Der deckt 03A und 03B zusammen ab. Hier steht die längere Begründung dazu.

Frage 1, wie viele der erzeugten Dateien hast du selbst geschrieben?

Keine einzige. Von den über dreissig Dateien fasst du im ganzen Modul etwa acht an: das Manifest, die zwei Gradle-Dateien, den Versionskatalog, die Layouts, strings.xml und deine Java-Klassen.

Warum das zählt: Wer glaubt, er müsse alles verstehen, verliert Zeit an backup_rules.xml und rules.keep. Die brauchst du nie. Lern die acht, ignoriere den Rest, und schau nach, wenn dich eine Fehlermeldung dorthin schickt.

Frage 2, was passiert bei zwei Activities mit MAIN und LAUNCHER?

Deine App bekommt zwei Symbole im App-Menü, mit demselben Namen. Der Benutzer sieht die App doppelt und weiss nicht, welche er antippen soll.

Der intent-filter beantwortet nicht die Frage "welche Activity gibt es", sondern "was soll das System starten, wenn jemand die App öffnet". Es kann nur eine Antwort geben.

Warum das zählt: Am Tag 3 kommen vier weitere Activities dazu. Die häufigste Art, sie einzutragen, ist Kopieren des bestehenden Blocks. Wer dabei den intent-filter mitkopiert, sieht den Fehler erst im App-Menü.

Frage 3, welche der drei Zahlen entscheidet über die Anzahl Geräte?

minSdk, bei uns 26. Sie nennt die älteste Android-Version, auf der deine App startet. Alles darunter kann sie nicht einmal installieren.

AngabeBei unsWas sie bedeutet
minSdk26Die älteste Version, auf der die App läuft. Nur diese schliesst Geräte aus
targetSdk36Die Version, gegen die getestet wurde. Android schaltet danach sein Verhalten
compileSdk36.1Die Version, mit der übersetzt wird. Sagt nichts über Geräte aus

Der Assistent rechnet es dir vor: API 26 erreicht rund 98.4 Prozent aller Geräte, API 36 nur rund 7.5 Prozent.

Warum das zählt: Wer compileSdk für die Gerätezahl hält, wählt aus Vorsicht ein zu tiefes compileSdk und kann dann neue Bausteine nicht benutzen. Die zwei Zahlen ziehen in verschiedene Richtungen. Hoch übersetzen und tief laufen lassen ist der übliche Weg.

Frage 4, du benennst eine id im Layout um. Wo schaust du danach?

In der Java-Klasse, die dieses Layout benutzt. Jede id lebt an zwei Orten: im XML wird sie mit @+id/ vergeben, im Code wird sie mit R.id. benutzt.

Warum das zählt: Der Compiler warnt dich nicht. R.id.main existiert nach dem Umbenennen zwar nicht mehr, aber wenn irgendwo sonst im Projekt noch eine id main steht, kompiliert es weiter und liefert zur Laufzeit null. Genau das ist der Absturz aus C1.

Die Beobachtungsstelle

C1 gegen C2, die App stürzt nach dem Umbenennen ab

Was du siehst: Die App startet gar nicht sichtbar. Der Emulator zeigt kurz nichts oder eine Meldung WissQuiz keeps stopping.

Was im Logcat steht:

Caused by: java.lang.NullPointerException: Attempt to invoke virtual method
  'void android.view.View.setPadding(int, int, int, int)' on a null object reference
    at ch.wiss.m335.quiz.MainActivity.lambda$onCreate$0(MainActivity.java:38)

Die Ursache: findViewById(R.id.main) findet nichts mehr und gibt null zurück. Der Listener bekommt null und ruft darauf setPadding auf.

Die drei Schritte, mit denen du dorthin kommst: Caused by suchen, darunter die erste Zeile mit ch.wiss.m335.quiz suchen, die Zeilennummer ablesen. Genau wie in 01B.

Der Merksatz für das ganze Modul. Eine id steht an zwei Orten. Im XML wird sie vergeben, im Code wird sie benutzt. Wer eine ändert, zieht die andere nach.

Warum tvTitle alle vier Anker hat. Ein Element, das gegen alle vier Kanten des Parent gespannt ist und wrap_content gross ist, landet genau in der Mitte. Das ist der übliche Weg zum Zentrieren im ConstraintLayout. Du brauchst dafür keine Angabe wie gravity.

tvStage hängt oben an @id/tvTitle, nicht am Parent. Darum rutscht es mit, wenn der Titel länger wird. Beachte: hier steht @id ohne Plus, weil die id schon vergeben ist.

Die fertige MainActivity

Datei app/src/main/java/ch/wiss/m335/quiz/MainActivity.java.

package ch.wiss.m335.quiz;

import android.os.Bundle;
import android.util.Log;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

/**
 * Startbildschirm der Quiz-App.
 *
 * Das Gerüst steht, mehr nicht. Zu sehen ist nur der Titel.
 * Die Knöpfe zu den weiteren Bildschirmen kommen später, sobald es
 * Bildschirme gibt, zu denen sie führen können.
 *
 * Der Insets-Block unten gehört zum Template. Ab Android 15 zeichnet das
 * System bis unter Statusleiste und Navigationsleiste. Ohne diesen Block
 * liegt der Titel unter der Uhr.
 */
public class MainActivity extends AppCompatActivity {

    /**
     * Log-Tag für das ganze Modul 335.
     *
     * Bewusst nicht "M335". Diese Zeichenfolge steckt auch im
     * Paketnamen ch.wiss.m335.quiz. Das Suchfeld im Logcat sucht im
     * Freitext über alle Spalten, und damit träfe "M335" jede Zeile
     * unserer App statt nur die selbst geschriebenen.
     */
    private static final String TAG = "Modul335";

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);

        // 16dp eigener Rand, in Pixel umgerechnet über die Dichte des Geräts.
        final int extraPadding = Math.round(16 * getResources().getDisplayMetrics().density);

        // Wichtig: der eigene Rand wird zu den System-Insets dazugerechnet.
        // Wer hier nur setPadding(extraPadding, ...) schreibt, verliert den
        // Abstand zur Statusleiste wieder.
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.clMain), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(
                    systemBars.left + extraPadding,
                    systemBars.top + extraPadding,
                    systemBars.right + extraPadding,
                    systemBars.bottom + extraPadding);
            return insets;
        });

        Log.d(TAG, "MainActivity onCreate, das Projekt steht");
    }
}

Lösungen zu den Übungen

Übung 1, eine zweite Log-Zeile

@Override
protected void onPause() {
    super.onPause();
    Log.d(TAG, "MainActivity onPause, die App geht in den Hintergrund");
}

Die Methode gehört in dieselbe Klasse, ausserhalb von onCreate. Der Aufruf super.onPause() ist Pflicht. Ohne ihn wirft Android beim Verlassen eine Ausnahme, weil die Basisklasse ihre eigene Arbeit nicht machen konnte.

Was du dabei nebenbei siehst: Eine Activity hat einen Lebenszyklus. onCreate läuft einmal beim Erzeugen, onPause jedes Mal beim Verlassen. Am Tag 3 nutzt du das aus, wenn der beste Wert nach der Rückkehr aktuell sein muss.

Übung 2, der Rand wird grösser

final int extraPadding = Math.round(40 * getResources().getDisplayMetrics().density);

Genau eine Zahl. Die 16 wird zur 40.

Warum das die richtige Stelle ist: Der Wert steht an einem Ort und wird an vier Stellen benutzt. Wer stattdessen die vier Werte im setPadding einzeln anpasst, hat dieselbe Zahl viermal im Code und vergisst beim nächsten Mal eine davon.

Übung 3, erklären

Eine gute Erklärung nennt beide Stellen und die Richtung dazwischen.

"Im XML habe ich die id vergeben, mit @+id/clMain. Im Java wird sie mit findViewById(R.id.main) gesucht. Diesen Namen gibt es nicht mehr, also kommt null zurück. Auf null kann man kein setPadding aufrufen, und darum stürzt die App ab, sobald sie startet."

Wer dazu noch sagen kann, warum der Compiler nicht gewarnt hat, hat es ganz verstanden: findViewById darf zur Übersetzungszeit nicht wissen, welche Views im Layout stehen. Es prüft erst beim Laufen.

Zur Zusatzaufgabe steht hier bewusst nichts. Es gibt mehrere richtige Wege, und die Frage danach musst du selbst beantworten können.

So prüfst du das Ganze

  1. Projekt öffnen, warten bis die Statusleiste unten leer ist.
  2. Im Fenstertitel steht WissQuiz.
  3. Run auf dem Emulator Medium Phone API 36.1.
  4. Auf dem Emulator steht mittig WissQuiz und darunter Das Projekt steht.
  5. Im Logcat nach tag:Modul335 filtern. Dort steht deine Zeile.
  6. Im App-Menü des Emulators heisst das Symbol WissQuiz.

Punkt 5 ist der wichtigste. Wenn der Filter tag:Modul335 etwas zeigt, sind Paketname, Log-Tag und Emulator-Verbindung alle drei in Ordnung. Ab hier ist jeder Fehler ein eigener.
