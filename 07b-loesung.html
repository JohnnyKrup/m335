Antworten zu den Denkfragen

1. Die Punktzahl steht rechts, und nirgends steht das Wort rechts. Wer sorgt dafür?

Der mittlere Block. Er hat layout_width="0dp" und layout_weight="1". Das heisst wörtlich: rechne meine Breite nicht aus meinem Inhalt aus, sondern gib mir allen Platz, der übrig bleibt. Was im LinearLayout danach kommt, wird dadurch an den Rand geschoben.

Das ist ein anderes Denken als eine Ausrichtungsangabe. Du sagst nicht, wo etwas hin soll. Du sagst, wer den Platz nimmt, und der Rest ergibt sich. Dieselbe Technik hältst du im Spielbildschirm die Punktzahl neben Frage 1 von 5.

Warum gravity="end" hier nicht reicht. gravity schiebt den Inhalt innerhalb einer View. Wenn die View selbst nur so breit ist wie ihr Text, gibt es innen nichts zu schieben. Erst wenn jemand Platz freigibt, kann etwas nach rechts rutschen.

2. Warum baut applyFilter eine zweite Liste?

Weil allEntries der Bestand ist. Filterst du ihn selbst, sind die anderen Einträge weg. Beim Zurückschalten auf Alle Kategorien gibt es nichts mehr, das zurückkommen könnte. Du siehst dann für immer nur noch die Sport-Einträge.

Und der zweite Teil der Frage ist der interessante. Du würdest es beim Nachprüfen wahrscheinlich nicht merken. Sobald du den Bildschirm verlässt und wieder öffnest, läuft onResume, lädt alles neu, und der Fehler ist scheinbar weg. Er kommt beim nächsten Filtern wieder.

Das ist die unangenehmste Sorte Fehler. Er verschwindet genau dann, wenn du ihn anschauen willst. Wer so etwas sucht, muss den Fehler ohne Verlassen des Bildschirms nachstellen, also Sport, dann sofort Alle Kategorien.

3. Nach dem Filtern auf Sport steht dein bester Sport-Eintrag auf Rang 1. Ist das ein Fehler?

Nein. Und du hast es selbst so gebaut, in 06C. In onBindViewHolder steht position + 1. Die Position ist die Stelle in der Liste, die der Adapter gerade hat. Filterst du, ist das eine andere Liste, also sind es andere Positionen.

Woher es kommtBeim Filtern

Die Rangnummeraus der Position in der angezeigten Listezählt neu bei 1 an

Für eine Rangliste ist das genau richtig. Rang 1 in Sport ist eine sinnvolle Auskunft, und niemand erwartet in einer Sport-Rangliste die Nummer aus der Gesamtwertung.

Und der Merksatz: der Rang gehört nicht zum Eintrag, er gehört zu der Liste, in der er steht. Das ist dieselbe Entscheidung wie in 06A, wo ihr den Rang bewusst nicht ins Datenmodell aufgenommen habt. Was sich aus der Reihenfolge ergibt, wird nicht gespeichert.

HighscoreActivity.java, die ganze Klasse

package ch.wiss.m335.quiz;

import android.os.Bundle;
import android.util.Log;
import android.view.View;
import android.widget.AdapterView;
import android.widget.ArrayAdapter;
import android.widget.Spinner;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;
import androidx.recyclerview.widget.LinearLayoutManager;
import androidx.recyclerview.widget.RecyclerView;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

import ch.wiss.m335.quiz.data.HighscoreStorage;
import ch.wiss.m335.quiz.model.HighscoreEntry;
import ch.wiss.m335.quiz.model.QuestionBank;

/**
 * Zeigt die Rangliste, seit 07B mit einem Filter nach Kategorie.
 *
 * Drei Bausteine gehören zusammen, und alle drei sind nötig: das
 * Zeilenlayout, der Adapter und der LayoutManager. Wer einen davon
 * vergisst, sieht eine leere Fläche.
 *
 * Seit 07B hält diese Klasse zwei Listen. allEntries ist der ganze
 * Bestand und bleibt vollständig. Der Adapter bekommt nur den
 * Ausschnitt, der zum Filter passt. Eine Liste zum Behalten, eine zum
 * Zeigen.
 */
public class HighscoreActivity extends AppCompatActivity {

    /** Log-Tag für das ganze Modul 335. */
    private static final String TAG = "Modul335";

    /**
     * Der erste Eintrag im Filter, "Alle Kategorien".
     *
     * Er schränkt nichts ein. Alle weiteren Einträge stehen in
     * derselben Reihenfolge wie QuestionBank.categories(), nur um eine
     * Stelle verschoben.
     */
    private static final int FILTER_POSITION_ALL = 0;

    /** Der Adapter, der die Zeilen füllt. */
    private HighscoreAdapter adapter;

    /** Die Auswahl oben. Sechs Einträge. */
    private Spinner spnFilter;

    /**
     * Der ganze Bestand, sortiert. Die Liste zum Behalten.
     *
     * Sie wird nie gefiltert. Gefiltert wird nur, was der Adapter
     * bekommt. Wer diese Liste selbst filtert, kann danach nicht mehr
     * auf "Alle Kategorien" zurückschalten.
     *
     * Gleich hier mit einer leeren Liste belegt, denn der Filter meldet
     * sich schon, bevor onResume zum ersten Mal geladen hat.
     */
    private List<HighscoreEntry> allEntries = new ArrayList<>();

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_highscore);

        // 16dp eigener Rand, in Pixel umgerechnet über die Dichte.
        final int extraPadding = Math.round(16 * getResources().getDisplayMetrics().density);

        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.clHighscore), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(
                    systemBars.left + extraPadding,
                    systemBars.top + extraPadding,
                    systemBars.right + extraPadding,
                    systemBars.bottom + extraPadding);
            return insets;
        });

        RecyclerView rvHighscore = findViewById(R.id.rvHighscore);
        rvHighscore.setLayoutManager(new LinearLayoutManager(this));

        adapter = new HighscoreAdapter();
        rvHighscore.setAdapter(adapter);

        // Derselbe Baustein wie die Kategoriewahl in der GameActivity.
        spnFilter = findViewById(R.id.spnFilter);
        spnFilter.setAdapter(new ArrayAdapter<>(this,
                android.R.layout.simple_spinner_dropdown_item, buildFilterLabels()));

        // Ohne diesen Listener passiert beim Auswählen nichts. Kein
        // Absturz, keine Meldung, die Liste bleibt einfach stehen.
        spnFilter.setOnItemSelectedListener(new AdapterView.OnItemSelectedListener() {

            @Override
            public void onItemSelected(AdapterView<?> parent, View view, int position, long id) {
                applyFilter();
            }

            @Override
            public void onNothingSelected(AdapterView<?> parent) {
                // Kommt bei einem Spinner nicht vor. Eine Auswahl ist
                // immer gesetzt, notfalls die erste.
            }
        });

        Log.d(TAG, "HighscoreActivity onCreate");
    }

    /**
     * Lädt die Rangliste jedes Mal neu, wenn der Bildschirm erscheint.
     *
     * Geladen wird der ganze Bestand. Was davon zu sehen ist,
     * entscheidet danach applyFilter.
     */
    @Override
    protected void onResume() {
        super.onResume();

        allEntries = HighscoreStorage.getAll(this);

        // Die beste Punktzahl zuoberst. Integer.compare(b, a) sortiert
        // absteigend.
        Collections.sort(allEntries, (a, b) -> Integer.compare(b.getScore(), a.getScore()));

        Log.d(TAG, "highscores loaded, total=" + allEntries.size());

        applyFilter();
    }

    /**
     * Baut die Beschriftungen für den Filter.
     *
     * Zuoberst "Alle Kategorien", danach dieselben Einträge wie bei der
     * Kategoriewahl im Spiel. Der Eintrag "Alle" heisst hier
     * "Gemischt", weil er etwas anderes bedeutet.
     *
     * Die Liste wird abgeleitet und nicht abgeschrieben. Kommt eine
     * Kategorie dazu, steht sie automatisch auch im Filter.
     *
     * @return die sechs Beschriftungen in Anzeigereihenfolge
     */
    private List<String> buildFilterLabels() {
        List<String> labels = new ArrayList<>();
        labels.add(getString(R.string.filter_all));

        for (String category : QuestionBank.categories()) {
            if (QuestionBank.CATEGORY_ALL.equals(category)) {
                labels.add(getString(R.string.category_mixed));
            } else {
                labels.add(category);
            }
        }

        return labels;
    }

    /**
     * Zeigt nur die Einträge, die zum gewählten Filter passen.
     *
     * Gefiltert wird die Anzeige, nicht der Bestand. allEntries bleibt
     * vollständig, sonst wäre nach dem ersten Filtern alles andere weg.
     *
     * Die Schleife ist dieselbe wie in QuestionBank.byCategory. Dort
     * wird ein Fragenbestand nach Kategorie durchsucht, hier eine
     * Rangliste.
     */
    private void applyFilter() {
        int position = spnFilter.getSelectedItemPosition();

        if (position == FILTER_POSITION_ALL) {
            adapter.setEntries(allEntries);
            Log.d(TAG, "filter=all, shown=" + allEntries.size());
            return;
        }

        // Position 0 ist "Alle Kategorien" und steht nicht im Bestand.
        // Darum liegt die gesuchte Kategorie eine Stelle weiter vorne.
        String category = QuestionBank.categories().get(position - 1);

        List<HighscoreEntry> shown = new ArrayList<>();
        for (HighscoreEntry entry : allEntries) {
            if (entry.getCategory().equals(category)) {
                shown.add(entry);
            }
        }

        adapter.setEntries(shown);
        Log.d(TAG, "filter=" + category + ", shown=" + shown.size());
    }
}

Die Stelle aus B4, aufgelöst

Du hast auf Sport gefiltert und gesehen, dass die Ränge wieder bei 1 anfangen. Die Auflösung steht bei Denkfrage 3.

Die Frage, die im Unterricht meistens kommt: wie würde man denn den Gesamtrang anzeigen?

Man müsste für jeden angezeigten Eintrag seine Position in allEntries suchen. Also etwa so:

// So NICHT bauen. Nur zum Anschauen.

Drei Gründe, warum das hier nicht gebaut wird:

  • Der Adapter kennt allEntries nicht, und das ist Absicht. Er müsste die Liste bekommen, und dann kennt er zwei Listen statt einer.
  • indexOf ist eine Suche. Sie läuft in onBindViewHolder, also bei jedem Scrollen. Genau das, was dort nicht hingehört.
  • Es beantwortet die falsche Frage. Wer auf Sport filtert, will die Sport-Rangliste sehen.

Lösungen zu den Übungen

Kommentare nachziehen. Eine mögliche Version des Klassenkommentars steht oben im Code. Wichtig ist nicht der Wortlaut, sondern dass drei Dinge darin vorkommen: dass es zwei Listen gibt, welche davon vollständig bleibt, und wer den Ausschnitt bekommt.

Und die zwei Zahlwörter im Adapter. Der Konstruktor des ViewHolder sucht seit heute vier TextViews, nicht drei. Dasselbe im @return von onCreateViewHolder. Beides sind Kommentare, die in 06C noch stimmten. Genau daran erkennst du die teure Sorte: sie werden nicht falsch, weil jemand sie falsch geschrieben hat, sondern weil der Code darunter weitergewachsen ist.

Übung 1a, das Gewicht wegnehmen. Ohne weight ist der mittlere Block nur so breit wie sein längster Text. Die Punktzahl klebt direkt daneben und steht bei jeder Zeile an einer anderen Stelle. Das Wort rechts kommt trotzdem nirgends vor, weil die Ausrichtung nicht angegeben, sondern erzeugt wird. Wer den Platz nimmt, bestimmt, wo der Rest landet.

Übung 1b, die drei Punkte wegnehmen. Ohne maxLines="1" darf der Name umbrechen. Er wird zweizeilig, und die ganze Zeile wird höher als die anderen. ellipsize allein nützt nichts, weil es erst greift, wenn der Text nicht umbrechen darf. Die zwei Angaben gehören zusammen.

Übung 2, der leere Filter. Wer eine leere Fläche sieht, denkt in den allermeisten Fällen, die App sei kaputt. Kein Mensch kommt darauf, dass er selbst gefiltert hat und dort einfach nichts ist. Ein leerer Zustand braucht immer einen Text. In 07C bauen wir ihn, dort bei der Fragenliste.

Übung 3, erklären. Die kürzeste richtige Antwort lautet: eine Liste hält alles, die andere hält das, was gerade zu sehen ist. Ohne die zweite müsste man die erste kaputtmachen, um zu filtern, und danach gibt es kein Zurück mehr.

Zur Zusatzaufgabe steht hier bewusst nichts. Ein Hinweis trotzdem, weil die Schätzung mehr wert ist als der Code: mit einem TabLayout allein ersetzt du den Spinner fast eins zu eins. Sobald du zusätzlich wischen willst, kommen ViewPager2 und ein Fragment pro Reiter dazu, und das ist ein deutlich grösserer Schritt.

  8. Zurück auf Alle Kategorien. Alles ist wieder da.
  9. Filter auf Gemischt. Nur die Runden über alle Kategorien.
  10. Neue Runde spielen, eintragen, Rangliste öffnen. Der neue Eintrag ist da, der Filter steht wieder auf Alle Kategorien.
  11. Gerät drehen. Auswahl und Liste bleiben.
  12. Logcat unter tag:Modul335: bei jedem Wechsel eine Zeile filter=Sport, shown=2.

Punkt 8 ist der einzige, der wirklich etwas Neues prüft. Alles andere sieht man sofort. Dass der Bestand heil geblieben ist, sieht man nur, wenn man zurückschaltet, ohne den Bildschirm zu verlassen.

Was noch nicht gut ist, und das mit Absicht

  • Der leere Filter zeigt eine leere Fläche. Kommt in 07C bei der Fragenliste, dort wird der leere Zustand richtig gebaut.
  • Die Filterauswahl wird nicht gemerkt. Beim nächsten Öffnen steht wieder Alle Kategorien. Das ist für eine Rangliste in Ordnung, und es zu merken wäre eine eigene kleine Lektion über Zustand.
  • Kein Klick auf eine Zeile. Der Listener im ViewHolder kommt in 08C, wenn eine Frage zum Bearbeiten geöffnet wird.
  • Die Rangliste bleibt in den SharedPreferences. Nur die Fragen bekommen in 07C eine Datenbank. Die Begründung dafür hast du in 06A selbst hergeleitet.
  • Kein DiffUtil. Bei jedem Filterwechsel wird die ganze Liste neu gezeichnet. Bei fünf Einträgen sieht das niemand.

Was als Nächstes kommt

07C, Room. Der Fragenbestand zieht aus dem Code in eine Datenbank um. Das ist der grosse Block des Tages, 90 Minuten am Stück, und es ist die erste Abhängigkeit, die wirklich in den Versionskatalog eingetragen werden muss.

Was du heute gebaut hast, kommt dort sofort wieder: eine Liste, ein Adapter, und die Trennung zwischen dem Bestand und dem, was gerade zu sehen ist. Nur kommen die Daten dann nicht mehr aus einer Datei, sondern aus einer Abfrage.
