Ressourcen und R

Modul 335 Mobile Applikationen, Nachschlageblatt. Lesezeit etwa 9 Minuten. Version 1 vom 04.09.2026.

Warum dein Text nicht im Code steht, was der Ordner res enthält, und was die Klasse R eigentlich ist.

Dieses Blatt ist die Ergänzung zu XML verstehen. Dort steht, was das Zeichen @ im Layout bedeutet. Hier steht, warum es das überhaupt gibt und was dahinter liegt.

01 Die Frage, um die es geht

Du willst eine Überschrift setzen. Der naheliegende Weg wäre dieser.

// Das läuft. Und trotzdem macht es in Android niemand.
tvTitle.setText("Meine Einkaufsliste");

Der Grund ist nicht Ordnung, und es ist auch keine Geschmacksfrage. Der Grund ist, dass dieselbe App auf sehr verschiedenen Geräten läuft. Eines steht auf Deutsch, eines auf Französisch. Eines läuft im Dunkelmodus. Eines hat einen viel feineren Bildschirm als das andere.

Ein fest eingebauter Text kann auf all das nicht reagieren. Er ist ein einziger Wert, und er steht mitten in einer Methode.

Der eine Satz, der alles trägt: du schreibst nicht den Text hin, du schreibst einen Namen hin. Welchen Wert Android hinter dem Namen hervorholt, entscheidet es beim Anzeigen, nach der Situation des Geräts.

Alles Weitere auf diesem Blatt folgt daraus. Der Ordner res ist die Sammlung dieser Werte, und R ist das Verzeichnis dazu.

02 Der Ordner res, von aussen

So sieht er in deinem Projekt wirklich aus. Links der Ordner, rechts was darin liegt.

   app/src/main/
        |
        +-- java/            dein Code
        |
        +-- res/             alles, was der Benutzer sieht oder hört
        |     |
        |     +-- layout/          activity_main.xml, item_shopping.xml
        |     +-- values/          strings.xml, colors.xml, themes.xml
        |     +-- values-night/    themes.xml, dieselben Namen, andere Werte
        |     +-- drawable/        Formen und Bilder, meist als XML
        |     +-- mipmap-hdpi/     das App-Symbol in einer Grösse
        |     +-- mipmap-xhdpi/    dasselbe Symbol, feiner
        |     +-- xml/             Einstellungen, die niemand sieht
        |
        +-- AndroidManifest.xml

Alles unter res gehört zur App, aber nichts davon ist Code. Es wird nicht übersetzt, es wird mitgeliefert. Darum kannst du einen Text ändern, ohne eine einzige Zeile Java anzufassen.

03 Der Zusatz hinter dem Ordnernamen

Dir ist sicher aufgefallen, dass manche Ordner einen Anhang tragen. values und values-night. mipmap-hdpi und mipmap-xhdpi. Das ist der eigentliche Trick, und er ist einfacher, als er aussieht.

Der Anhang ist eine Bedingung. Für dich und für R heissen beide Ordner gleich, nämlich values. Erst auf dem Gerät entscheidet Android, aus welchem der beiden es liest.

AnhangAndroid nimmt diesen Ordner, wennBei uns im Projekt
kein Anhangimmer, wenn nichts Besseres passt. Der Rückfallwertvalues/, layout/, drawable/
-nightdas Gerät im Dunkelmodus läuftvalues-night/themes.xml
-hdpi, -xhdpi, -xxhdpider Bildschirm so fein istdas App-Symbol, sechsmal abgelegt
-de, -frdas Gerät auf dieser Sprache stehtgibt es bei uns nicht. Wir haben nur eine Sprache
-landdas Gerät im Querformat istgibt es bei uns nicht

Der Merksatz: du schreibst den Namen einmal, du legst die Datei mehrmals an. Im Code ändert sich dabei kein Zeichen. Genau deshalb steht der Text nicht im Java.

Und daraus folgt eine Regel für den Rückfallwert. Der Ordner ohne Anhang muss vollständig sein. Wenn ein Name nur in values-night steht, findet Android ihn am Tag nicht.

04 Was R ist und wer es baut

R ist eine Java-Klasse. Sie steht in keinem Ordner, den du siehst, und du hast sie nie geschrieben. Sie entsteht bei jedem Bau neu.

// Sinngemäss das, was der Bau erzeugt. Du siehst diese Datei normalerweise nicht.
public final class R {
    public static final class string {
        public static final int title_main = 0x7f0f001a;
        public static final int btn_save   = 0x7f0f001b;
    }
    public static final class id {
        public static final int tvTitle = 0x7f0900c3;
    }
}

Jede Ressource bekommt eine Zahl, und der Name daneben ist nur für dich da. Wenn du R.string.title_main schreibst, übergibst du in Wahrheit diese Zahl.

Über R stimmt
Sie wird bei jedem Bau neu erzeugtja
Sie enthält für jede Ressource eine Konstanteja
Nach einer neuen id kann ein neuer Bau nötig sein, damit sie gefunden wirdja
Du musst sie von Hand pflegennein, nie

Der Merksatz: R ist das Inhaltsverzeichnis, das der Bau erzeugt. Kein Eintrag unter res, kein Name in R. Und umgekehrt: was du in res anlegst, steht nach dem nächsten Bau in R.

Deshalb hilft bei einem hartnäckig roten Namen oft schlicht ein neuer Bau mit Ctrl+F9.

05 Die zwei Schreibweisen, in einem Satz

Dieselbe Ressource heisst im XML anders als im Java.

Im LayoutIm Java-Code
@string/btn_saveR.string.btn_save
@layout/activity_mainR.layout.activity_main
@+id/tvTitleR.id.tvTitle

Aus dem @ wird ein R., aus dem Schrägstrich ein Punkt. Mehr ist es nicht. Warum im Layout einmal @+id und einmal @id steht, erklärt XML verstehen im Abschnitt über das Zeichen @.

06 Was in strings.xml gehört und was nicht

Nicht jeder Text auf dem Bildschirm ist eine Ressource. Die Trennlinie ist nicht die Länge und nicht der Ort, sondern die Frage: wer ändert diesen Text?

BeschriftungDaten
Wer ändert siedu, oder ein Übersetzerder Benutzer, oder die Datenbank
BeispieleSpeichern, Menge, Noch keine Runde gespieltMilch, 2.50, der Text einer Frage
Wohinstrings.xmlin den Code oder in die Datenbank

Die Namensregel

Im Projekt steht sie als Kommentar zuoberst in strings.xml: was_wofuer, alles klein, mit Unterstrich.

<string name="title_main">Meine Einkaufsliste</string>
<string name="btn_save">Speichern</string>
<string name="hint_article">Artikel</string>
<string name="error_required">Pflichtfeld</string>

Der Name ist ein Java-Bezeichner, der Wert nicht. Aus dem Namen wird eine Konstante in R, darum sind darin nur Kleinbuchstaben, Ziffern und Unterstriche erlaubt. Kein Bindestrich, kein Umlaut, kein Leerzeichen. Im Wert daneben darfst du alles schreiben, Umlaute und Satzzeichen inklusive.

07 Texte mit einer Lücke

Sehr oft soll ein Text eine Zahl enthalten, die erst zur Laufzeit feststeht. Dann zerlegst du ihn nicht, sondern lässt eine Lücke.

<!-- in strings.xml -->
<string name="amount_format">%1$.2f CHF</string>
<string name="progress_format">Frage %1$d von %2$d</string>
// im Java, die Lücken werden von links nach rechts gefüllt
tvProgress.setText(getString(R.string.progress_format, aktuelle, gesamt));
ZeichenHeisst
%1$dder erste Wert, als ganze Zahl
%2$dder zweite Wert, als ganze Zahl
%1$sder erste Wert, als Text
%1$.2fder erste Wert, als Kommazahl mit genau zwei Stellen

Die Nummer vor dem Dollarzeichen ist der Grund, warum das Ganze so umständlich aussieht. Sie sagt, welcher Wert gemeint ist, und nicht der Platz im Satz. In einer anderen Sprache steht die Zahl vielleicht am Anfang statt am Schluss. Mit der Nummer bleibt trotzdem klar, welcher Wert wohin gehört.

In einem Adapter hast du kein getString zur Hand, denn eine Adapter-Klasse ist keine Activity. Dort läuft es über den Context, also context.getString(...). Warum das so ist, steht in Die Activity von innen.

09 Wenn du einen neuen Text brauchst: die Reihenfolge

1 Entscheide, ob es überhaupt eine Beschriftung ist. Wer ändert diesen Text? Sind es Daten, hör hier auf

2 Trag ihn in strings.xml ein, unter einem Namen nach dem Schema was_wofuer

3 Verweise darauf. Im Layout mit @string/name, im Java mit R.string.name

4 Hat der Text eine Lücke, setz ihn mit getString(R.string.name, wert) statt direkt

Der Prüfschritt am Schluss: such im ganzen Projekt nach dem sichtbaren Text. Er darf genau einmal vorkommen, nämlich in strings.xml. Findest du ihn ein zweites Mal, steht er irgendwo noch fest eingebaut.

11 Prüfe dich selbst

  1. Nenne zwei Situationen, in denen Android für denselben Namen einen anderen Wert holt
  2. Warum darf ein Ressourcen-Name keinen Bindestrich haben, der Wert daneben aber schon?
  3. Ein Name steht nur in values-night. Was passiert am Tag?
  4. Du legst eine neue id im Layout an und das Java findet sie nicht. Was probierst du zuerst?
  5. Milch und Speichern stehen beide auf dem Bildschirm. Welches der beiden gehört in strings.xml, und woran erkennst du das?
  6. Wozu ist die Nummer in %1$d gut, wenn die Werte doch von links nach rechts eingesetzt werden?

Die Antworten stehen alle auf diesem Blatt. Wenn du eine nicht findest, hast du den Abschnitt überschlagen, und genau der ist der, den du brauchst.
