B2Lesen und einlesen. Die Schleife schreibst du selbst. 11 Min

Alles in diesem Schritt kommt in deine QuizDatabase. TAG, DB_NAME und instance stehen seit 07C da, es kommt nur diese Konstante dazu:

/** Der Startbestand, liegt unter app/src/main/assets. */
private static final String ASSET_NAME = "questions_m335.json";

Dann das Lesen aus assets. Das ist der neue Mechanismus, darum steht er vollständig da:

/**
 * Liest den Startbestand aus dem Ordner assets.
 *
 * assets ist kein res-Ordner. Was dort liegt, wandert unverändert in
 * die App und bekommt keine R-Nummer. Gefunden wird es über den
 * Dateinamen, und darum meldet auch kein Compiler einen Tippfehler
 * darin.
 *
 * Fehlt die Datei, liefert diese Methode ein leeres Array. Die App
 * läuft dann weiter und zeigt den leeren Zustand. Im Logcat steht der
 * Grund.
 *
 * @param appContext der Context der App
 * @return der Inhalt der Datei, oder ein leeres JSON-Array
 */
private static String readAsset(Context appContext) {
    StringBuilder builder = new StringBuilder();

    try (BufferedReader reader = new BufferedReader(new InputStreamReader(
            appContext.getAssets().open(ASSET_NAME), StandardCharsets.UTF_8))) {

        String line;
        while ((line = reader.readLine()) != null) {
            builder.append(line);
        }

    } catch (IOException e) {
        Log.e(TAG, "asset not found: " + ASSET_NAME, e);
        return "[]";
    }

    return builder.toString();
}

Die runde Klammer nach try schliesst am Ende automatisch, was du darin öffnest. Ohne StandardCharsets.UTF_8 kommen deine Umlaute kaputt an.

Und jetzt das Einlesen. Deine Vorlage ist HighscoreStorage.getAll aus 06B. Zwei Dinge sind hier anders. In jeder Frage steckt ein zweites JSONArray mit den vier Antworten, und das Ergebnis geht nicht in eine Liste, sondern ins Dao.

Erstell die Methode nach der Beschreibung im Rahmen, mit eigenem Code:

 *
 * (HIER: zwei bis drei Zeilen, was die Methode tut und wann)
 *
 * @param appContext der Context der App, für den Zugriff auf assets
 */
private static void seedIfEmpty(Context appContext) {
    QuestionDao dao = instance.questionDao();

    try {
        ... hier den Text aus readAsset in ein JSONArray verwandeln ...

        ... hier über alle Einträge des Arrays laufen ...

            ... das JSONObject an der Stelle i holen ...

            ... daraus das innere Array mit dem Schlüssel answers holen ...

            ... ein neues QuestionEntity anlegen ...

            ... seine acht Felder setzen, die id NICHT ...

            ... die Frage ins Dao schreiben ...

        Log.d(TAG, "seed done, count=" + dao.count());

    } catch (JSONException e) {
        // Die Datei ist da, aber sie passt nicht zum erwarteten Aufbau.

Die acht Setter heissen setText, setAnswer1 bis setAnswer4, setCorrectAnswer, setCategory, setDifficulty. Der Schlüssel answers wird auf vier Setter verteilt, die id wird weggeworfen.

B3Aufrufen und den Zähler beobachten. 7 Min

Der Aufruf kommt in deine getInstance, innerhalb des if (instance == null). Eine bestehende Zeile ändert dabei ihren Platz. Dort steht seit 07C das hier, direkt nach dem build():

// build() legt die Datei noch nicht an. Das passiert erst beim
// ersten Zugriff, also bei count() gleich hier darunter.
Log.d(TAG, "database opened, name=" + DB_NAME
        + ", questions=" + instance.questionDao().count());

Ersetz diesen ganzen Block durch den hier:

seedIfEmpty(appContext);

// Erst nach dem Seed, damit die Zahl den Endstand meldet. In 07C
// stand hier eine Null, ab jetzt sind es dreissig.
Log.d(TAG, "database opened, name=" + DB_NAME
        + ", questions=" + instance.questionDao().count());

Die Reihenfolge ist der ganze Punkt. Bliebe die Log-Zeile oben stehen, würde sie zählen, bevor etwas eingefügt ist, und für immer null melden. Der Kommentar darüber stimmt ebenfalls nicht mehr, darum wird er mitgetauscht.

Der Aufruf gehört innerhalb des if und nicht darunter. Steht er ausserhalb, läuft er bei jedem Zugriff auf die Datenbank und nicht nur beim Aufbau. Der Compiler meldet davon nichts.

Deine MainActivity ruft getInstance seit 07C in ihrer onCreate. Der Startbestand läuft also beim Start der App. Jetzt starten und Fragen verwalten öffnen.

Der Titel lautet jetzt Fragen (30), und darunter stehen dreissig Zeilen. Im Logcat steht seed done, count=30.

Und jetzt der eigentliche Teil dieses Schritts. Drück nochmals auf Run, warte den Neustart ab und öffne Fragen verwalten wieder. Schau auf den Zähler im Titel.

Es steht Fragen (60) da. Beim dritten Start werden es neunzig.

Es ist ein Fehler, und er steckt im Namen. seedIfEmpty prüft nirgends, ob die Tabelle leer ist. Sie schreibt dreissig Zeilen, jedes Mal, wenn die Datenbank neu aufgebaut wird, und das passiert bei jedem Start. Beim Beenden verschwindet das Feld instance.

Die vier Zeilen, die fehlen, kommen ganz an den Anfang der Methode, direkt nach der Zeile mit dem dao:

int existing = dao.count();
if (existing > 0) {
    Log.d(TAG, "seed skipped, count=" + existing);
    return;
}

Die sechzig Zeilen, die schon drin sind, gehen davon nicht weg. Lösch die App-Daten einmal: lange drücken auf das App-Symbol im Emulator, dann App-Info, dann Speicher, dann Speicher löschen.
