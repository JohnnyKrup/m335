Antworten zu den Denkfragen

Diese vier Fragen kommen im 02B Check als Quizfragen wieder. Hier steht die längere Begründung dazu.

Frage 1, warum kann match_parent im ConstraintLayout nicht dasselbe leisten?

match_parent heisst "so gross wie mein Elter". Im ConstraintLayout hat der Elter aber keine feste Grösse, an der sich ein Kind orientieren könnte, denn seine Grösse hängt selbst von den Kindern und ihren Constraints ab. Darum ist die Angabe dort mehrdeutig.

0dp ist die eindeutige Anweisung: nimm den Platz zwischen meinen zwei Constraints.

Frage 2, warum braucht der Trennstreifen eine Höhe?

wrap_content wickelt sich um den Inhalt. Ohne Inhalt ist das Ergebnis null. Wer einen Streifen sehen will, muss die Höhe angeben.

Warum das zählt: Dieselbe Falle trifft dich später bei jedem Platzhalter, jeder Trennlinie und jedem leeren Container.

Frage 3, welche zwei Angaben machen vier Buttons gleich breit?

layout_weight="1" und layout_width="0dp". Erst zusammen ergeben sie gleiche Breiten. Jede allein reicht nicht.

Frage 4, dein Rand wirkt nicht. Wo suchst du zuerst?

In MainActivity.java. Konkret bei der Frage, ob dort jemand nach dem Laden des Layouts noch etwas setzt.

Warum das zählt: Wer hier "im XML weitersuchen" antwortet, hat die Reihenfolge XML zuerst, Code danach noch nicht verinnerlicht. Der Code läuft nach dem XML und darf alles überschreiben. Diese Reihenfolge erklärt später auch, warum ein setText im Code den Text aus dem Layout ersetzt.

Die fertige MainActivity

Datei app/src/main/java/ch/wiss/m335/formular/MainActivity.java.

package ch.wiss.m335.formular;

import android.os.Bundle;

import androidx.activity.EdgeToEdge;
import androidx.appcompat.app.AppCompatActivity;
import androidx.core.graphics.Insets;
import androidx.core.view.ViewCompat;
import androidx.core.view.WindowInsetsCompat;

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        EdgeToEdge.enable(this);
        setContentView(R.layout.activity_main);

        // 5 dp in Pixel umrechnen. setPadding rechnet in Pixeln, nicht in dp.
        final int extraPadding =
                Math.round(5 * getResources().getDisplayMetrics().density);

        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(
                    systemBars.left   + extraPadding,
                    systemBars.top    + extraPadding,
                    systemBars.right  + extraPadding,
                    systemBars.bottom + extraPadding);
            return insets;
        });
    }
}

Warum genau so

  • extraPadding wird vor dem Listener berechnet und ist final. Ein Lambda darf nur auf lokale Variablen zugreifen, die sich nicht mehr ändern. Ohne final würde es hier zwar meistens auch gehen, weil Java das selbst erkennt. Mit final steht die Absicht aber im Code.
  • Die Rechnung steht ausserhalb des Listeners, weil sie sich nie ändert. Innen würde sie bei jedem Drehen neu ausgeführt. Kein Drama, aber unnötig.
  • Es wird addiert, nicht ersetzt. Damit bleibt der Schutz vor Uhr und Navigationsleiste erhalten und dein eigener Rand kommt dazu.

Lösungen der Übungen

Übung 1, ein viertes Feld

Direkt unter dem Geburtsdatum, noch innerhalb von llForm:

<TextView
    android:id="@+id/tvCity"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="Wohnort" />

<EditText
    android:id="@+id/etCity"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:inputType="textPostalAddress"
    android:hint="Wohnort" />

Begründung. Du musstest an llForm selbst nichts ändern. Seine Höhe steht auf wrap_content, es wächst also von allein mit. Das ist der ganze Sinn eines LinearLayout: du hängst hinten etwas an und der Rest ordnet sich neu.

textPostalAddress ist die passende Angabe. text würde auch gehen, ist aber unpräziser. Der Unterschied ist auf dem Emulator kaum sichtbar, auf einem echten Gerät ändert er die Autovervollständigung.

Übung 2, der Streifen wird dünn
<View
    android:id="@+id/vwDivider"
    android:layout_width="0dp"
    android:layout_height="1dp"
    android:layout_marginTop="8dp"
    android:layout_marginBottom="8dp"
    android:background="#79747E"
    ... >

Begründung. Bei 1 dp Höhe wird die Farbe wichtig. Ein Strich in einem hellen Grau ist auf hellem Hintergrund kaum sichtbar. Genau darum arbeiten Trennlinien in Material Design mit 1 dp, aber mit einem klar dunkleren Ton.

Der marginTop hat hier keinen sichtbaren Effekt. Der Streifen hängt nur unten an der Buttonreihe, oben ist er an nichts angeheftet. Über ihm ist einfach leerer Raum. Wenn dir das aufgefallen ist, hast du die Übung ganz verstanden. Ein Margin wirkt nur dort, wo etwas dagegen drückt.

Übung 3, das Geburtsdatum begrenzen
<EditText
    android:id="@+id/etBirthDate"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:inputType="date"
    android:maxLength="10"
    android:hint="dd.mm.yyyy" />

Begründung. maxLength begrenzt die Zeichenzahl, sonst nichts. Es prüft nicht, ob ein gültiges Datum dasteht. 99.99.9999 hat zehn Zeichen und wird angenommen.

Das ist ein wichtiger Punkt für später. Das Layout kann Eingaben nur begrenzen, nicht prüfen. Echte Prüfung passiert im Code. Das machst du am Tag 3 bei Quiz 5.

Übung 4, erklären

Es gibt keine Musterformulierung, aber eine gute Erklärung enthält diese drei Punkte.

  1. Im LinearLayout gibt es eine feste Richtung. Der Container weiss immer, wie breit er ist. match_parent heisst dort schlicht: so breit wie er. 0dp allein ergibt dort null Breite, es wird erst durch layout_weight sinnvoll.
  2. Im ConstraintLayout gibt es keine Richtung. Jedes Kind hängt an Ankern. Der Container hat keine Breite, die er einem Kind anbieten könnte, bevor die Kinder platziert sind. 0dp heisst dort: berechne meine Breite aus meinen zwei Ankern.
  3. Das gleiche Wort, zwei Bedeutungen. Was 0dp bedeutet, entscheidet nicht das Element selbst, sondern sein direkter Elter. Darum musst du beim Lesen eines Layouts immer zuerst nach oben schauen.

Punkt 3 ist der eigentliche Lerninhalt. Wer nur 1 und 2 sagt, hat es beschrieben. Wer 3 sagt, hat es verstanden.

Zur Zusatzaufgabe

Hier steht bewusst keine Lösung. Die Zusatzaufgabe bleibt offen. Wenn du sie gemacht hast, zeig sie deiner Lehrperson und erklär deinen Weg.

Ein Hinweis darf sein: Es gibt mindestens drei brauchbare Wege. Einen über einen Scroll-Container, einen über eine eigene Layout-Datei für das Querformat, und einen über kleinere Abstände. Alle drei haben einen Nachteil. Die Frage im Auftrag zielt genau auf diesen Nachteil.

Die zwei Sätze, die zählen

Zu B2 gegen B3

Eine gute Notiz klingt etwa so: "Mit wrap_content war Abbrechen der breiteste Button und Löschen der schmalste. Mit 0dp waren alle vier gleich breit."

Wer notiert hat "es sah besser aus", hat geschaut, aber nicht beobachtet. Der Unterschied ist der Punkt der Übung.

Zu C4, dem Querformat

Eine gute Notiz benennt eine konkrete Folge. Zum Beispiel: "Im Querformat ist der Bildschirm so flach, dass die Buttonreihe das Feld Geburtsdatum überdeckt." Oder: "Das unterste Feld ist nicht mehr sichtbar, und ich kann nicht scrollen."

Genau dieser Befund ist die Brücke zur Zusatzaufgabe und später zum Testen am Tag 4.
